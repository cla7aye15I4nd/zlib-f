# The overlay certificates (memLevel 1 and 2)

This directory holds the tools behind the `lit_bufsize = 256` (memLevel 2) and `lit_bufsize = 128`
(memLevel 1) cases of the dynamic overlay room (`TinyOverlay`). The proof is in Lean; these tools find the certificate and
test the statement on the real C. They are evidence and generators, not proof.

## What is proved

`ZlibF/Math/DeflateOverlayCertificate.lean`, theorem `certificate` (checked):

    71 + Σ_v entryCost(ll v) + Σ_v entryCost(dl v) + E ≤ 1852

for the code lengths `ll` (286 literal/length entries) and `dl` (30 distance entries) and the
actual frequencies of one block with at most 255 symbols. `E` is the excess per occurrence:
`x + e − 9` for a length code with `e` extra bits at length `x`, `x + e − 15` for a distance code.
`entryCost` is 2 for a zero length and `max(κ0[x], 3)` for a length `x`, where `κ0` is the
reference bit-length code `[2,7,7,5,5,4,4,4,4,3,4,4,7,7,7,7,7,3,7]`.

The facts it uses:

- Kraft in each tree: `Σ 2^(15 − x) ≤ 2^15` over the nonzero lengths;
- the Fibonacci bound for every used code: `f·F(x+1) + F(x) ≤ 258` and `1 ≤ x ≤ 15`;
- a code with a nonzero length and no occurrence has index ≤ 2 (zlib's forced leaves);
- the end-of-block frequency is 1, there are at most 255 symbols, and there are as many length
  codes as distance codes.

`ZlibF/Proof/trees.c.overlay-scan-cost.lean`, theorem `scan_cost_le` (checked): the bit-length
symbols that `scan_tree` counts, each at its `κ0` length plus extra bits, cost at most the entry
costs of the lengths.

So if the header is at most `71 + Δ + Σ_k f_k·(κ0_k + xbits_k)` (batch 1's reference-code bound,
`f` the bit-length frequencies), the header plus the excess is at most `1852 + Δ`. The budget is
`8·256 − 25 = 2023`, so the room holds when Δ ≤ 171.

## The certificate

`overlay_cert.py` solves a small linear programme over the multipliers (`lpsolve.c`, a dense
simplex): a Kraft multiplier per tree, a symbol multiplier, a balance multiplier, an allowance per
class of entries (by tree, kind and extra bits) and one per forced leaf. It rounds them to
multiples of 1/8, raises each allowance to the least value that makes every entry fit, and
checks every inequality again with exact rational arithmetic. With `--lean` it writes the Lean
replay: each class is a sixteen-case `omega` check (one case per length), and the shares are
summed with `mass` lemmas. No `decide` on a large term is used.

## memLevel 1

`ZlibF/Math/DeflateOverlayCertificate128.lean` (generated by `overlay_cert_choice.py --size 128`), theorems
`certificate_none`, `certificate_dist`, `certificate_lit` (checked): for the lengths, the actual
frequencies and the header length `H` of a dynamic block with at most 127 symbols,

    H + E ≤ 999.

Besides the memLevel 2 facts (with the Fibonacci weight 130), it uses two rows that bound `H`:

- the header row: `2·(H − 71 − Δ)` is at most the sum of the region charges. The charges come from
  `scan_cost_region` (`ZlibF/Proof/trees.c.overlay-scan-region.lean`) with the reference code
  `κ1 = [2,8,8,6,5,4,3,4,4,3 | 16:7, 17:3, 18:3]`: in the literal region (0..256) a length costs
  `2·max(κ1[x], 3) + 9` and a zero 1; in the length and distance regions a length costs
  `2·max(κ1[x], 3)` and a zero 4. The 9 pays for the run of zeros the entry ends;
- the choice row: `H + Σ fl·ll + Σ fd·dl + 1 ≤ Σ fl·sl + 5·Σ fd` (`choice_row`, the dynamic choice
  per code, `sl` the fixed lengths).

Forced leaves are split into three cases: none; only in the distance tree, which then has two
nonzero lengths; in the literal/length tree, which then has two (`trees.c.build.two-leaves`). The
cases need `Δ ≤ 132`, `Δ ≤ 201` and `Δ ≤ 343`. The multipliers come from an exact LP (z3), rounded
to multiples of 1/1024; the header and choice rows carry the weights `wh` and `1 − wh`.

## memLevel 2 with the region scan and the choice row

`ZlibF/Math/DeflateOverlayCertificate256.lean` (`overlay_cert_choice.py --size 256`): the same
certificate at `lit_bufsize = 256` with `κ0`, region charges 6 and 2 in the literal region, 0 and 4
in the others (scaled by 2), weight 258, at most 255 symbols, budget 2023. The cases need
`Δ ≤ 640`, `Δ ≤ 818` and `Δ ≤ 946`. The bridge is `deflate.c.engine.overlay-mem2c`
(`dynamic_overlay_256c`). The first memLevel 2 certificate above (no choice row) needs `Δ ≤ 171`.

`deflate.c.engine.overlay-tiny-headers.tiny_overlay_of_headers`: `TinyOverlay` follows from the
two header bounds `HeaderRefBound Δ₂` (memLevel 2, `Δ₂ ≤ 640`) and `HeaderRefBound128 Δ₁`
(memLevel 1, `Δ₁ ≤ 132`).

## Tests

- `regenerate.sh`: regenerates the three Lean files and compares them with the repository copies
  (`PYTHON` must have the z3 module for memLevel 1).
- `check.sh` (with `ZLIB_SRC` set to the pinned zlib checkout): the statement test on the real C.
  `check.c` hooks `_tr_flush_block` after `build_bl_tree` (any block, dynamic or not), checks each
  fact above on the actual code lengths and frequencies, the scan bound, and the final bound, and
  searches for the tightest block. In about 940,000 blocks every fact held, with at least 609
  bits of slack against an earlier bound of 1892 (so at least 569 against 1852). With
  `MEMLEVEL=1` it checks the memLevel 1 facts (region scan, header row, choice row, two leaves,
  lengths at most 9) and `H + E ≤ 999` on every dynamic block: about 453,000 dynamic blocks and
  the two saved tightest blocks, smallest slack 266 bits, largest repair excess against κ1 −58.
  It also reports the exact left sides of the proved inequalities (smallest slack, about 965,000
  blocks): memLevel 2 certificate `71 + entry costs + per-occurrence excess ≤ 1852`, 538 bits;
  assembly at Δ = 160 against 2023, 635 bits; memLevel 1, the largest header both rows allow at
  Δ = 115 plus the excess against 999, 203 bits. Set `DELTA1`, `DELTA2` to change the Δ used.
- `header_lp.py`: batch 1's first programme over length histograms, kept for comparison.
