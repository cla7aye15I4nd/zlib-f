# 术语表

规格与证明中用到的术语，按读者需要的顺序排列。状态用语的定义见[参与贡献](checking/contributing.md)和[进度](progress.md#scope)。

**目标（target）。** 项目对一个 C 函数或调用序列要证明的陈述。它的 Lean 名字以 `Goal.` 开头。

**命题（goal）。** 写在 `ZlibF/Spec/` 中的 Lean 命题。只有类型与命题完全一致的定理才算证明了它。

**已检查（checked）。** 定理在 `dev` 上，且该提交上快速关卡为绿。**已验收（accepted）。** 定理还已登记，且验收套件在某个具名提交上全部通过。

**已登记（registered）。** 列入 `tests/audit/theorems.txt`。

**不计划（not planned）。** 项目不做的目标，从不称为已证明。

**故障（Fault）。** 模型中未定义行为的结果。C 能到达的每个未定义行为都引发 `Fault.ub`。安全定理证明没有任何运行会引发它。

**堆与指针。** `ZlibF/Runtime/` 中的内存模型。新内存中的指针是 NULL。证明要说明指针字段在读取之前已被写入。

**前置条件。** 定理对输入的假设。比 `zlib.h` 允许的范围更窄的前置条件要写在定理的文档注释中，并列入[偏差](deviations.md)。

**分离前置条件。** 调用者的缓冲区彼此不重叠，也不与流自己的存储重叠。`zlib.h` 用文字说明，定理把它写成假设。

**表示不变量。** 每次调用都保持的流状态性质，例如压缩流的 `DGood` 与解压流的 `Good`。由初始化函数建立。

**`StreamBuffers`。** 关于 `next_in`、`avail_in`、`next_out`、`avail_out` 的假设。每个范围或为 NULL，或可读（输出范围可写）；两者都不在流自己的存储内；输入与输出范围互相分离。`Goal.inflate` 与 `Goal.deflate` 以它为前提。

**序列命题。** 关于同一个流上任意调用序列的陈述，例如 `inflate_sequence`。

**差分测试。** 用同一输入分别运行真实 C 与 Lean 翻译并比较结果。它是忠实度的证据，不是证明。

**证明变异体。** 故意写错的翻译，例如去掉一个检查。健全的证明必须在它上面失败。

**快速关卡。** `build` 与 `no-sorry` 两个任务，每次推送和拉取请求都运行。

**验收套件。** 公理关卡、命题精确匹配、证明变异体和差分测试。每晚在 `main` 上运行，也可按需运行。

**里程碑。** `inflate` 证毕、`deflate` 证毕、一个序列命题证毕，或约二十个新检查通过的目标。
