# Glossary

Short definitions of terms used across the documents. Each entry names where the
exact definition lives. When an entry and its source disagree, the source wins.

## Targets and status

| Term | Meaning |
| --- | --- |
| Target | One fixed proposition listed in `tests/audit/goals.txt`. The generated block in [progress](progress.md) gives the current count and status of every target. |
| Goal | A target's Lean statement, in `ZlibF/Spec/` (for example `ZlibF.Spec.Public.Goal.inflate`). Goals are fixed; a proof must match the statement exactly. |
| Registered proof | A theorem listed in `tests/audit/theorems.txt` whose type matches a target and whose audit passes. "Proved" in a report also needs the four required CI statuses green on a named commit. |
| Locally checked | Built and audited on one machine, not yet accepted by CI. Never reported as proved. |
| Blocked | A target with a recorded counterexample or confirmed obstacle. Only the generator's blocker index can mark a target blocked. |
| Scoped result | A theorem about a restricted part of a target's domain (fixed level, fixed history shape). It does not prove or narrow the public target. [Deviations](deviations.md) lists the scopes. |
| Engine file | One of the `ZlibF/Proof/deflate.c.engine.*` (and similar `inflate.c.default-*`) modules. Most prove scoped default-configuration histories, not the universal invariant a public goal needs. |

## Invariants

| Term | Meaning |
| --- | --- |
| `Good` | Inflate representation invariant: the stream record, its state and window are live and owned, the state is well formed (window, bit counts, internal pointers), block numbers are unique and the allocator's fresh region is unused. Defined in `ZlibF/Proof/inflate.c.base.lean`. |
| `DGood` | The deflate counterpart of `Good`: live stream and state, the four buffers, state-field ranges, uniqueness, freshness and the tree invariant. Defined in `ZlibF/Proof/deflate.c.base.lean`. |
| `GzGood` | Representation invariant of a `gz_state` handle: mode, path and message strings, and optional buffers. Defined in `ZlibF/Proof/gzlib.c.base.lean`. |
| `PosInv` | Numeric invariant of the gz position fields that keeps `gztell64` in the signed 64-bit range. Defined in `ZlibF/Proof/gzlib.c.simple.lean`. |
| `OpenState` | The state a successful gz open establishes. Defined in `ZlibF/Spec/Public/GzOpen.lean`. |
| `DefAlloc` | The stream uses the default `zcalloc`/`zcfree` allocator, the only one the model has. |
| Universal invariant | An invariant preserved by one call from every reachable state, not only along one fixed history. The open public goals need these. |
| Frame | The part of the heap a call may change. A frame clause says every other block is unchanged. |

## Specification vocabulary

| Term | Meaning |
| --- | --- |
| `C1`–`C7` | Labels of the abstract API-model goals in `ZlibF/Spec/Api/Goals.lean`: `C1` round trip, `C2`/`C3` decode valid and reject invalid streams, `C4` dictionaries and headers, `C5` bounds, `C6` copy, `C7` gz files. They are about the model, not the translated C. |
| Ordinary data epoch | The part of a stream history built from ordinary calls only (no midstream raw-dictionary replacement, priming, header capture or recovery). For it, the sequence targets relate accepted and produced bytes to the independent format. Advanced operations keep their own per-call and safety targets. See [the advanced-operation boundary](checking/contract-review.md#the-advanced-operation-boundary). |
| `detectLag` | The API model's bound on how late inflate reports invalid data. The value 8 has a counterexample; see [the API model](design/api-model.md). |
| Domain witness | A concrete reachable state that satisfies a theorem's precondition, showing the precondition is not empty. Required for top-level theorems. |
| `Fault.ub` | The model's result for C undefined behaviour. A theorem that excludes it proves the call has no UB. |
| Fuel | The fixed iteration bound every translated loop carries. Running out is a fault, so termination is part of each theorem. |

## Checking vocabulary

| Term | Meaning |
| --- | --- |
| Four required statuses | `build`, `no-sorry`, `audit` and `difftest`. `audit` aggregates `audit_core`, `audit_selftest` and `audit_mutants`; `difftest` aggregates `diff_core` and `diff_harness`. See [checking](checking/README.md). |
| Lock | A generated file under `tests/audit/` (`statements.lock`, `policy.lock`, `trusted.lock`, …) that records reviewed statement types or protected file hashes. Regenerated by `scripts/verification.py regenerate`, never edited by hand. |
| Proof mutant | A deliberate change to a translation (a dropped check, an off-by-one) that must make that function's proof fail. See [proof mutants](checking/proof-mutants.md). |
| Scoped admission | The single reviewed scoped proof-mutant case (`tests/proofmut/deflate-default-scoped-null-output.py`). It is checked against an independently approved baseline commit stored in a repository variable; that commit's `policy.lock` and `trusted.lock` must equal the candidate's. |
| Differential test | Running the real C and the translation on the same inputs and comparing results. It is evidence of fidelity, not proof. |
| `to confirm` | Marks a reading of the C that a proof must still confirm. |
