# 已审查的递归执行辅助声明

> **历史记录。** 本文描述写作当时的流程：锁文件、重新生成的锁、经批准的基线以及对锁差异的审阅。这些机制后来已被移除，现在没有锁文件，见[防作弊](../anti-cheating.md)。下文只应作为那个快照的证据来读。

审计列出了六个针对全逻辑定义生成的执行辅助声明。
每个条目均为列出的名称后跟 `._unsafe_rec`。

| 逻辑定义 | 递减参数 |
| --- | --- |
| `Zlib.Trees.Math.nextCode` | 自然数前驱。 |
| `Zlib.Trees.Math.reverseLowBits` | 自然数前驱。 |
| `Zlib.Trees.Math.scanCount` | 自然数前驱。 |
| `Zlib.Trees.Math.scanMax` | 自然数前驱。 |
| `Zlib.Trees.Proofs.Math.blMaxIdx` | 自然数前驱。 |
| `Zlib.Trees.Proofs.tallyCalls` | 列表尾部。 |

这些逻辑定义具有经过检查的 `Nat.rec` 或 `List.rec` 方程。
实际生成的类型和分支主体已独立检查。
主体比较仅将辅助声明的自引用替换为其全逻辑对应项。递归参数也已直接检查。
被检查的环境中没有任何安全声明引用这些辅助声明。
它们不存在于已注册定理的逻辑依赖闭包中。

仅将这些确切的声明添加到现有的执行辅助声明列表中。
它们的完整导出语法已被锁定。这不允许在项目源代码中进行部分定义，
也不确立编译器或机器代码的正确性。
当前的接受状态仍见[概览](../overview.md)。

## 已审查的霍夫曼和符号辅助声明

这十九个确切条目已独立审查并批准注册。
它们是全逻辑定义生成的执行辅助声明。
它们的类型与逻辑对应项匹配。在仅将辅助声明的自引用替换为该逻辑定义后，
所有四十四种构造器情况均通过定义相等性匹配。树相等性检查两种树构造器；
霍夫曼见证检查燃料以及空森林、单元素森林和较长森林。
被检查的导入闭包中没有任何安全声明引用这些辅助声明。
完整的生成类型和主体包含在审计导出中。

| 逻辑定义 | 递减参数 |
| --- | --- |
| 树权重、高度、叶子、正权重和兄弟谓词 | 树的子节点。 |
| 派生的树表示和相等性 | 树的子节点；相等性还匹配另一棵树。 |
| 斐波那契对、累积计数、秩和、加权和以及质量 | 自然数前驱。 |
| 最深非零计数、长度搜索和溢出修复迭代 | 自然数前驱。 |
| 最小值提取、表示的符号字节和直方图计数 | 列表尾部。 |
| 确定性霍夫曼见证 | 燃料前驱。 |

这些是添加到现有编译器辅助声明列表中的确切已审查条目。
它们不允许项目源代码中标记为部分或 unsafe 的声明。
现有的声明检查、公理限制和目标问题仍然有效。
注册使用生成的锁并要求 CI 接受。


## 普通请求计数器拆分器

计数器证明生成了九个额外的普通全匹配拆分器。
它们的类型和完整主体与现有锁定声明在定义上相等。
此比较使用完全透明性并禁用智能展开。它包括单子结果拆分、
两个慢决策拆分及其稀疏情况，以及收尾尾部拆分和稀疏情况。
这些是普通的内核检查定义，没有新的执行辅助声明例外或不支持的声明类型。

重新生成添加了九个语义条目。它不更改任何现有语义条目
和任何已注册定理陈述。策略锁记录了计数器范围文档、
其四个源变异运行器以及新的语义锁摘要。编译器辅助声明例外列表未更改。
公开的 deflate 和序列目标仍然开放。仍需 CI 接受。


## 重新填充框架中的配对与单子匹配辅助声明

重新填充框架证明生成了两个普通全匹配定义。
UInt32/Bool 对消除器和单子结果拆分的类型和完整主体
与现有锁定定义在定义上相等。比较规范化宇宙参数，
使用完全透明性并禁用智能展开。直接检查还将对辅助声明
识别为单个 Prod.casesOn 应用。

重新生成添加了两个语义条目，不更改任何现有语义条目，
并保持已注册定理陈述不变。策略锁仅记录新的语义锁摘要。
执行辅助声明例外列表和审计逻辑未更改。
