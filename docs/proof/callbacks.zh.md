# 回调解码：所有权与有限输入

源文件为 `infback.c`。调用者拥有窗口，并提供输入／输出回调。[API](../spec/api/inflate-back.md)陈述公开契约，[进度](../progress.md)记录当前进展。这些论证和源代码解读不认证完整回调解码器。

## 回调定义域与终止

回调假设描述调用者提供的代码，与禁止假定库内被调用函数契约是两回事。调用 `inflate_fast` 或 `inflate_table` 的定理，仍需关于该翻译后函数的定理。

| 迁移论证中的条件 | 相对 API 的边界 |
| --- | --- |
| 默认分配器，或初始化时被替换的空分配器字段 | 自定义分配器实现不在此模型范围内 |
| 窗口由字节块表示，从其偏移起具有 `2^windowBits` 字节空间 | 调用者必须提供有效可写范围 |
| 回调不分配或释放任何堆块 | 强于文档对返回输入所要求的生命周期 |
| 只有输入回调写自己的输入块 | 方便的所有权纪律，不完整刻画全部合法回调 |
| 回调不变量 `R` 只依赖其拥有的块 | 将回调效果与解码器状态分离，建立帧性质 |
| `InFinite` 限制仍能交付的输入 | 终止所需；API 不承诺回调最终结束 |

度量 `phi` 合并已保留位、剩余字节和仍可交付的输入。无限产出输入的回调可能使 `inflateBack` 永不返回，却不产生 C 未定义行为。有限输入定理必须明确这个前提，不能对公开接口允许的所有回调声称无条件终止。任何更窄的定理定义域都必须明确，并记录在[偏差记录](../deviations.md)中。

## 回调解码器

`inflateBackInit_` 分配状态但不清零，只写窗口设置、窗口指针、历史计数器与 `sane`。模型中新鲜整数任意，新鲜指针字段为空；后者弱于 C。证明必须说明每个指针在读取之前已被写入，仅无运行时故障还不够。`inflateBack` 使用的模式、位寄存器、码长和表指针在各路径中初始化：其时间顺序初始化论证仍 **待确认**。

窗口由调用者提供并拥有。`inflateBackEnd` 只释放状态。`ROOM` 在调用 `out` 前重设输出空间并写入 `whave`。`PULL` 只在当前输入耗尽时调用 `in`；返回零时设 `next = NULL` 并返回缓冲区错误。最终部分窗口的 `out` 调用发生在判断 `ret == Z_STREAM_END` 之前，因此也可能出现在错误路径，包括先前回调拒绝之后。最终收尾只回写 `next_in` 和 `avail_in`，不回写输出寄存器。

回调运行在共享堆上。实现的 `InCb` 接收当前输入指针，返回 `(count, newPointer)`；它不会像旧提案那样为 `&next` 分配真实单元。若回调保留该地址并随后经它写入，则不在此表示范围内。`OutCb` 接收窗口指针和长度，返回整数。

回调义务属于调用者前提，不是对 zlib 被调用函数的假定规范。它们包括：输入在下次 `in` 前保持有效可读，保留活动窗口切片与流状态，并对回调效果建立恰当帧性质。描述符存储可以与窗口分配共享空间，但须位于该切片之外。额外限制必须明确记录在[偏差记录](../deviations.md)中。顶层声明需要具体的已初始化示例。

仅回调会返回还不足以推出终止。输入回调可以提供无限多个空的非最终块。终止定理需要有限输入界限，或其他明确的进展条件。功能观察必须包含回调事件与失败；不能无条件承诺失败的输出恰好交付一次。

## 已安装表与窗口复制

表构造返回值的分类不能建立规范链接的界限。把输出与历史设为不同数组的快速路径定理，也不能覆盖输出位于回调窗口中的情形。实际调用者必须在返回堆上建立已安装表和复制所需前提。历史上的缺少 `whave` 报告仍 **待确认**；普通 inflate 的例子不能解决这个 API 的问题。
