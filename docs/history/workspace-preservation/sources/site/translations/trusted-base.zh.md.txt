# 内核没有建立的结论

内核依据 Lean 陈述检查证明。把结果应用到选定 C 源码，还依赖下列各项。
这些依赖经过审查、锁定和测试；仅编译证明不会消除它们。
声明、接受规则和当前状态分别见[安全](safety.md)、[验证政策](anti-cheating.md)和 [overview](overview.md)。

## 1. 内核与允许的公理

信任 Lean 内核以及 `propext`、`Classical.choice` 和 `Quot.sound`。
声明审计只允许这些公理。新的内核重放检查已编译证明的闭包；执行测试不能替代它。

## 2. 运行时与对象模式

`ZlibF/Runtime/` 定义翻译后的执行具有何种含义。`Space.lean` 提供对象引用和更新。
`Monad.lean` 提供故障、顺序执行和循环。`Ptr.lean` 提供指针算术、加载、存储和比较。
`Libc.lean` 建模所需的库操作；`Alloc.lean` 导入它。
`Schema.lean`、`Tables.lean` 和 `LibcTables.lean` 为每种结构体提供生成的记录、常量、堆表和操作。
它们的生成器和[运行时模式](runtime-schema.md)都是此依赖的一部分。

无故障定理针对的是这些定义。预期对应关系是，可达的 C 未定义行为变成 `Fault.ub`，
但须遵守下面的限制。无符号算术是模算术。每个翻译必须检查有符号算术、移位和转换。
循环的 fuel 为 `2^64`；耗尽它产生 `Fault.outOfFuel`，终止证明必须排除这种情况。

### 内存与库操作

堆为不同对象种类设置分离的表。释放后的块编号永不复用。
分配器仅在 `nextBlk` 这个身份尚未在那里使用时写入，否则产生故障。
`Fresh` 保护未来身份。初始堆在 `nextBlk` 以下的各表之间，也必须具有唯一块身份；
单独的 `Fresh` 不表达这个条件。

| 操作 | 需要审查的模型行为 |
| --- | --- |
| `memcpy`、`zmemcpy` | 即使长度为零也拒绝空指针，并拒绝重叠区间和只读目标。整记录复制使用 `copyK`，它拒绝把对象复制到自身。单纯的记录加载/存储对不检查重叠。 |
| `memmove` | 检查相同的区间和可写性，但允许重叠，并从原始源复制。 |
| `memset`、`zmemzero` | `Ptr.fill` 按元素计数并赋值；只有在给定用法中，它才表示字节 `memset` 或零填充。`Ptr.memset` 复制一个字节值。整记录清零存入明确的零记录。 |
| `strlen` | 要求表示的块内存在 NUL。 |
| 分配 | 新整数来自任意垃圾值函数；新指针字段为 NULL。`allocOk` 预言机决定失败。自动局部对象绕过该预言机，不消耗分配尝试次数。 |
| `free` | NULL 是空操作。否则，参数必须是所表示种类的一项活的可写分配的起点。没有分配来源标签。 |
| 字符串字面量 | `strLitRef` 指向生成的封闭 `strTable` 中一个静态、只读、以 NUL 终止的条目。它始终存活，身份稳定，永不释放。未知字面量文本产生故障。其他外部字符串使用不同的分配路径。 |

运行时不提供 `calloc`、`realloc`、格式化、`errno`、`abs` 或 `strerror` 的一般模型。
翻译提供它们所需的特定行为。这些定义也需要审查；放在 `Runtime/` 之外不会降低它们的语义作用。

### 表示缺口与证明义务

| 选择或缺口 | 对 C 声明的影响 |
| --- | --- |
| 未初始化指针变成 NULL | NULL 的比较、复制和释放可以在没有先前写入时成功。每次指针读取都需要先写后读的论证。初始化翻译明确将两个已分配的流状态记录清零；这不是新记录或自动 `z_stream` 存储的一般性质。要弥合此缺口，需要初始化跟踪，或为所有指针形式提供独立的未初始化值，并配有受检查操作和相应翻译改动。 |
| 每个单元一个垃圾值 | 整数定理对每个 `Heap.garbage` 量化，其索引为分配尝试和单元位置。但对一个单元的重复读取结果仍相同。当 C 允许不稳定的未指定值时，证明不得依赖这种一致性。 |
| 数组长度由谓词给出 | `WellFormed`、`Heap.RecordsWellFormed` 和 `Statics.WellFormed` 必须建立 C 长度。生成的保持引理维持它们。静态内容必须与定义它的 C 翻译匹配；运行时不会拿它们与 C 比较。 |
| 指针相等是结构相等 | 不同对象比较不等；悬空指针的相等比较不产生故障。证明不得依赖 C 不保证的结果，包括相邻对象边界处的相等。关系比较要求属于同一个活数组。 |
| 部分允许空指针算术 | `Ptr.add NULL 0` 返回 NULL。`Ptr.diff` 拒绝空参数，但 `Compress.ptrDiff` 对两个空指针返回零。对于相应 C 调用，这些选择需要单独的有定义性论证。 |
| 地址和布局模型不完整 | 没有一般的 ABI 地址、有效类型或记录字节视图模型。CRC 观察地址低位：堆字节块保留起点对齐约定；静态和嵌入式字节起点具有任意且稳定的余数。不改变已有存储即可配置这些元数据。按字节组装的字加载，不能解决 C 强制类型转换的别名语义。标量单元适配器可能省略别名。见[偏差](deviations.md)。 |
| 只读标记不完整 | 字节块、有名静态表和实例可以只读。表中的字块和记录不能表示这个限定。 |
| 指针构造检查不完整 | `Ptr.add` 检查结果，不检查手工构造的起始偏移是否有效。翻译审查必须排除对公开 `Ptr.ref` 构造器的无效使用。 |
| 不跟踪对象来源 | 由 `allocBytes` 创建的调用者块可以被翻译后的代码释放。当 API 禁止此行为时，frame 和所有权条款必须阻止它。错误种类的状态强制转换会比相应 C 访问更早产生故障。 |

这些是模型限制，不是悄悄缩窄公开定理的许可。
[运行时审查](checking/runtime-review.md)是关于这些选择的历史证据，不是对当前基线的独立批准。

### 表更新

`Tbl` 包装一个数组，读取时是块身份的全函数。缺失条目返回默认值（`none` 或 `false`）。
`upd` 的相同键、不同键和重复更新规则已由 `Tbl.get_set` 证明。

写入原语使用 `Space.modify` 移除、修改并放回数组，不保留一条先前数组链。
`Space.modify_eq` 陈述它与更简单的函数式 `put` 操作相等。
信任审查必须覆盖 `Tbl.get_set`、`Tbl.modify_eq`，以及每个生成的 `Space` 实例的
`modify` 和 `modify_eq`。操作引理使用 `put` 推理；执行性能不能建立它们之间的对应关系。
见[表更新审查](checking/runtime-tables-review.md)。

## 3. 手工翻译

`ZlibF/Zlib/` 中的翻译逐语句编写。内核不检查它与 C 的对应关系。
审查必须检查求值顺序、检查条件、算术、存储生命周期和效果。
不匹配就是翻译错误；必须修正并添加差分回归，不能通过改变定理来掩盖。
[翻译规则](design/translation.md)要求每个函数都有证据。测试清单为 `tests/list.txt`。

差分测试将有限执行与真实 C 比较。它们是忠实性的证据，不是证明。
特别是，结果一致且 sanitizer 没有报告，也不能建立 C 表达式具有有定义语义。

## 4. 选定源码

已验证源码由固定版本的 `zlib/` 子模块，加上按名称顺序应用的 `patches/*.patch` 组成。
子模块永不直接编辑。只有已确认且阻碍证明的上游错误，才允许补丁；补丁必须最小，
并与已提交的上游修复一致。修复合并且固定版本越过它之后，删除补丁。

[补丁登记](../patches/README.md)列出当前有效的补丁，并记录选定源码政策。
历史提案不会仅仅因为笔记提及，就成为已验证源码的一部分。

## 5. 配置与外部世界

首个目标是默认 x86_64 Linux/LP64 静态构建，使用默认分配器。
分配失败仍在范围内。其他上游配置和自定义分配器需要各自的对应关系论证；完整项目目标包含它们。

gz 文件世界和格式化模型是额外的受信任语义。
它们支持的文件种类、错误、转换和外部字符串分配，不表示每种操作系统或库行为。
回调正确性依赖明确的返回协议、有限输入界和窗口保持假设。
[偏差](deviations.md)记录对公开适配器的影响。编译器、操作系统和硬件正确性不在证明内。

## 6. 陈述与权威

证明可以建立一个不完整或错误的规格。审查者必须将目标、前置条件和有名规格标识，
与 [API](api/README.md)、[格式](format/README.md)及选定 C 比较。
他们还必须确认初始化建立不变量，而且调用者定义域没有缩小。

锁保存定义和定理类型；它们不批准其含义。
独立的基线审查和强制仓库保护提供这条权威边界。
[验证政策](anti-cheating.md)解释这一点。当前已检查结果和未解决义务应放在 [overview](overview.md)。
