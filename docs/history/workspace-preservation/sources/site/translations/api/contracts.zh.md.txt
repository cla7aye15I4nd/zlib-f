# 怎样阅读契约

[API 手册](README.md) · [流的共同规则](streams.md)

契约回答三个问题：调用者必须提供什么，调用返回时调用者可以依赖什么，以及调用期间什么可以改变？
阅读单个条目前，先阅读页面的共同规则。
这些规则提供内存、生命周期和构建假设，否则就需要在每个函数下面重复说明。

## 条目结构

| 部分 | 含义 |
| --- | --- |
| C 函数签名 | 函数的 C 名称和参数类型，保留声明宏。 |
| 用途 | 调用者试图执行的操作。 |
| Domain | 本契约覆盖哪些值、对象和调用历史。 |
| Pre | 调用前要求成立的条件，包括经过检查的拒绝情况。 |
| Post | 每条已说明的返回路径上的结果和保证。 |
| Effects | 读取、写入、分配、释放、文件操作和借用存储。 |
| 边界或错误 | 空输入、部分输出和拒绝等会改变结果使用方式的情况。 |

错误返回通常不会撤销已经完成的工作。
输出、指针推进、长度单元或文件位置可能已经改变。
应遵循所说明的返回路径和效果。特别是，解码时的分配失败可能发生在已经产生部分输出之后。

## 定义域和效果相互独立

**受限域（Restricted domain）**要求的不只是参数类型中的值。
指针通常必须指向活存储；句柄需要合法的调用历史；
合并校验值可能要求使用针对正确长度生成的算子。

**完整类型域（Full type domain）**覆盖选定构建中参数类型的每一个值，包括所说明的拒绝情况。
一个函数即使覆盖了每个标量值，整体定义域仍然可能受限，因为它的指针必须指向有效存储。
两者的区别不在于有限还是无限，也不在于有界还是无界。

| 效果 | 含义 |
| --- | --- |
| 纯计算 | 不读取调用者内存，也不改变状态，只计算结果。可以使用固定的库常量或表。 |
| 只读 | 读取调用者内存或流状态，并保持它们不变。借用结果仍归库所有。 |
| 有状态 | 可以写入调用者目标区或库状态，分配或释放存储，调用回调，或执行文件 I/O。 |

这些标签描述不同的性质。纯计算也可以具有受限域。
一个查询如果写入可选的标量结果，那么即使流保持不变，它仍有写入效果。

## 示例：合并两个 CRC

`crc32_combine_op` 不必再次读取原始字符串：

```text
Domain: Restricted domain.
Pre: crc1 is the CRC of A; crc2 is the CRC of B;
     op was generated for the representable nonnegative length of B.
Post: the result is the CRC of A followed by B.
Effects: pure computation.
```

A 的 CRC 指从零开始对 A 调用 `crc32` 所得的值。
A 和 B 是普通字节序列；不需要特殊的 CRC 类型。
即使调用不读取任何调用者内存，所生成的算子和正确长度仍然重要。
零长度和负长度的情况见[校验值条目](checksums.md)，
与标准的一致性见[格式模型](../format/README.md)。

## 共同阅读规则

除非条目另有说明，否则采用默认 LP64 Linux 静态构建和默认分配器。
可读和可写区间在整个调用期间包含所述数量的字节。
长度必须能由其参数类型表示。
活句柄已经初始化、尚未关闭，并且按顺序使用；调用者不会修改句柄拥有的状态。

在 Pre 成立时，契约要求执行终止且没有未定义行为，满足 Post，
并且只修改所述内存范围。
分配失败、部分结果和清理也属于这一要求。
[流的共同规则](streams.md)解释共同的所有权和 frame 义务；
[安全说明](../safety.md)定义模型中的故障。

这些是限定范围的文档契约。
更窄的 Pre 既不改变已登记的 Lean 目标，也不使被排除的调用成为未定义行为。
见[范围偏离](../deviations.md)和[已登记公开目标](../checking/goals.md)。
对源码的解读有待证明**确认（to confirm）**。
证明状态和剩余工作只记录在[概览](../overview.md)中。
