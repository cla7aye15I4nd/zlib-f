# 翻译 C，而不改变它的行为

翻译逐语句保留选定的 C 程序。证明困难不是重排检查、缓存读取、合并语句或替换算法的理由。
不一致就是翻译缺陷：对照 C 修正它，并加入差分回归测试。
差分测试提供忠实性的证据；它们不证明忠实性。

[架构](architecture.md)解释对象堆。[信任基础](../trusted-base.md)记录它的语义限制。
精确的记录字段与指针种类见生成的[运行时模式](../runtime-schema.md)。

## 翻译前先固定源码

翻译默认 x86_64 Linux 静态构建，采用 LP64 位宽。
应当针对 `zlib/` 加上有序补丁来确定预处理器选择，而不是针对未打补丁的检出版本或其他配置。
源文件映射到追加 `.lean` 后缀的同名文件：
`zlib/X.c` 变为 `ZlibF/Zlib/X.c.lean`；头文件遵循同样的规则。

保持 C 函数名。文档字符串以精确的 C 签名开头，包括原本存在的 `static`。
每个辅助函数都有独立定义。Lean 定义顺序可以遵循依赖顺序，但函数内部语句保持 C 顺序。
在翻译代码块的注释中列出对应的 C。对于状态机，还要记录哪些状态对应 C 标签。

## 保留求值与算术

按源码顺序展开宏。保留读取、写入、分支条件、提前返回和短路求值。
显式应用整数提升和通常算术转换。例如，在本目标上，`unsigned short + int` 按 `int` 计算。

| C 类型 | LP64 上的 Lean 类型 |
| --- | --- |
| `unsigned char` | `UInt8` |
| `unsigned short` | `UInt16` |
| `unsigned`, `unsigned int` | `UInt32` |
| `unsigned long`, `size_t`, `z_size_t` | `UInt64` |
| `int` | `Int32` |
| `long`, `z_off_t`, `z_off64_t` | `Int64` |

无符号运算按其位宽回绕。有符号运算必须检查可表示性。
移位必须检查 C 操作数位宽和计数，包括负计数。
Lean 中算术运算是全定义的，这本身不能说明某个 C 操作有效。

枚举常量有一个用于无符号状态字段的 `UInt32` 名称，以及一个带 `_i` 后缀、用于 C `int` 类型场景的 `Int32` 名称。
当宏与枚举常量重名时，需要的地方使用 `GZ_<name>`：
`GZ_COPY` 表示 `gzguts.h` 中的宏，`COPY` 则表示 `inflate.h` 中的枚举常量。

## 每个对象只表示一次

| C 对象或操作 | 表示 |
| --- | --- |
| 结构体 | 位于其种类对应的堆表中的记录，通过块标识引用 |
| `p->f` / `p->f = v` | 记录字段读取/更新，不进行 ABI 偏移运算 |
| 嵌入式数组 | 数组字段；复制记录也复制该数组 |
| 指向嵌入式数组的指针 | 指明记录、字段和索引的引用构造器 |
| 字节缓冲区 | 堆字节块与偏移 |
| `head` / `prev` 字数组 | 堆字块与元素偏移 |
| 静态表 | 静态引用或经过检查的常量表；存储产生故障 |
| 被取地址的局部变量 | 在声明处表示其存储，具有自动生命周期，并在每次返回前清理 |
| 字符串字面量 | 指向封闭、只读源码字面量表的 `strLitRef`；不分配 |
| `ZALLOC` / `ZFREE` | 默认分配器操作，包括失败预言机；自定义分配器不在选定模型内 |

模式由 C 头文件生成。翻译者通过经过审查的运行时流程请求补充模式；不能另行创造第二种记录布局。
生成的数组字段仍然需要其声明长度的事实。
涉及分配的定理还携带 `Fresh`，使分配无法覆盖已有对象。

自动局部存储不得消费分配器失败索引。赋予它 `ZALLOC` 的语义，会改变真实分配中哪一次失败。
同样，被取地址的局部变量在其 C 生命周期结束后不得继续存活。

## 显式处理新内存

新整数内容是任意的。定理必须对每个值成立，包括在 `prev` 已初始化部分之外，
或在匹配预读区中读取、复制的值。不能把这些内容替换成零。

本模型中的新指针字段为 NULL。这比 C 中的不确定指针更弱。
对于从新分配记录中读取的每个指针字段，要在翻译注释中指出先前的写入语句，并在证明中建立该顺序。
NULL 比较、复制和释放 NULL，都检测不出未写入字段。
不能仅因为 `Heap.garbage` 为一个单元提供稳定值，就假定对未初始化单元的重复读取一致。

`X.zeroed` 表示实际存在的整记录清零语句。`X.garbage` 表示新分配的内容。
两者不能互换。参见[安全性，第 3 节](../safety.md#3-faults-undefined-behaviour-and-model-gaps)。

## 使用相应的库操作

| C 操作 | 翻译规则 |
| --- | --- |
| 字节 `memcpy` / `zmemcpy` | `memcpyB`；保留区间与不重叠检查 |
| 整记录 `memcpy` | `copyK dst src`；它检查重叠，不同于单纯加载后存储 |
| `memmove` | 对应的移动操作，允许重叠 |
| 字节 `memset` | `memsetB` |
| 将较宽数组清零 | `Ptr.fill p 0 n`，使用正确的元素计数 |
| 用字节 `c` 填充较宽数组 | `Ptr.memset p c n`，在每个元素中复制 `c` |
| 整记录清零 | `stK p X.zeroed` |

`memcpy` 既复制已初始化值，也复制任意值。
即使复制长度为零，运行时遇到 NULL 也会产生故障。
建模的库操作按元素计数；C 字节计数必须正确转换。
`Libc.lean` 和生成的 `LibcTables.lean` 定义这些操作；
[信任基础](../trusted-base.md)列出了它们与 C 的差异。

## 让控制流保持可见

循环通过运行时循环或有界递归，在显式状态中携带局部变量。
`do … while` 先执行循环体，再测试条件。
循环中的 `break`、`continue` 和返回使用控制标签，保留它们不同的目的地。
需要时，`goto` 和 switch 的顺序贯穿使用显式程序计数器。

循环界限不允许提前终止。耗尽会产生 `Fault.outOfFuel`；终止证明必须排除该结果。
在已记录的模型差异约束下，让每个可达的未定义操作都以 `Fault.ub` 保持可见。
这包括指针边界、存活性、对只读对象的存储、无效比较、有符号算术和重叠复制。

## 让改动可以审查

交付镜像源码模块、函数级差分测试，以及翻译决定和对应 C 行的记录。
在拉取请求中报告实际运行过的检查。审计与变异证据遵循[检查指南](../checking/README.md)。
运行时改动需要独立审查，因为所有函数证明都依赖它的语义。

如果证明暴露出可能的上游缺陷，要保留公开定义域。
区分证明技术问题、错误规格、翻译不匹配和真实 C 缺陷。
最后一种必须有具体输入和 sanitizer 复现，才能称为已确认发现。
