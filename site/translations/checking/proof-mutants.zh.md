# 证明变异

证明必须拒绝其验证函数中故意引入的错误。证明变异会在临时副本中改变一个翻译函数，并要求失败发生在该函数的证明中。未修改的证明必须先通过。

这不同于 `tests/selftest.sh` 中的差分自测，后者要求执行比较检测到变异。只有测试能捕获的变异可能暴露证明覆盖缺失。证明拒绝变异是敏感性的证据，不证明变异改变了可观察行为，也不证明定理覆盖每一种错误。审查必须建立必需变异在某个允许输入上改变行为。

## 运行检查

在仓库根目录，使用已经预热的 `.lake` 构建缓存：

```sh
python3 scripts/verification.py mutants
bash tests/audit/proofmut.sh tests/audit/proofmut/adler32.tsv
bash tests/audit/proofmut.sh tests/audit/proofmut/crc32.tsv '^combine'
```

第一条命令构建项目、检查经解析的公开变异边界、重放原始精确公开证明，并在严格模式下运行模型列表及每个被引用的公开函数列表。其余命令运行单个旧式列表，还可以按变异名称过滤。它们在开发期间有用，但不能代替最终接受。

列表运行器把工作区和预热缓存复制到临时目录。它先构建列表中未修改的证明模块，将每个替换恰好应用一次，再只构建指定模块。报告的第一个错误必须位于预期证明模块。原始缓存保持不变。一次只运行一个变异。

| 判定 | 解释 |
| --- | --- |
| `KILLED` | 第一个错误位于预期证明模块。变异检查通过。 |
| `SAME ok` | 显式标记为等价的变异仍然能够构建。审查等价原因。 |
| `GAP (known)` | 有文档记录的证明缺口在开发模式下存活。它不构成覆盖，并且无法通过严格接受。 |
| `SURVIVED` | 没有合理说明的变异仍然能够构建。调查覆盖缺失或等价性。 |
| `BAD MUTANT` | 翻译或证明目录树之外的文件失败。修复变异。 |
| `WRONG PLACE` | 另一个证明先失败。这不满足指定函数的检查。 |
| `NO ERROR` | 即使重试一次，构建仍在没有识别到错误的情况下失败。未建立证明拒绝。 |
| `UNEXPECTED` | 标记为等价的变异失败。审查标记和变异。 |
| `NOT APPLIED` | 替换文本没有恰好出现一次，或未发生变化。更新变异。 |

被杀死的变异如果仍带有过时的 `gap:` 标记，也会失败。缺口闭合后，通过经过审查的审计更新移除标记。严格模式强制运行正基线并拒绝已知缺口。跳过基线不能支持最终接受。

## 公开入口要求

每个得到精确证明的公开入口都需要在 `tests/audit/public-mutants.json` 中有一条记录。记录给出对该函数翻译函数体的变异，并保持签名不变。解析器在不加载候选导入的情况下检查两个版本。对其他函数的变异、只改规格、注入声明和标记为证明缺口的情况都不算。

除重新构建指定证明模块外，公开检查还会取原始已登记的精确证明，并在其依赖闭包中只替换改变了的源码声明。新内核重放必须接受原始版本并拒绝变异。不相关定理失败，或一个带额外前提的更强定理失败，都不够。权威和锁定规则见[反作弊策略](../anti-cheating.md)。

## 列表格式

列表的每个变异占一行，用制表符分隔。以 `#` 开始的行是注释。

```text
NAME <TAB> FILE <TAB> OLD <TAB> NEW <TAB> PROOF_MODULES [<TAB> same:REASON | gap:REASON]
```

| 字段 | 含义 |
| --- | --- |
| `FILE` | 相对仓库根目录的翻译源码路径，例如 `ZlibF/Zlib/adler32.c.lean`。 |
| `OLD`、`NEW` | 替换文本。字面的 `\n` 表示一个换行；`OLD` 必须恰好出现一次。 |
| `PROOF_MODULES` | 位于 `ZlibF/Proof` 下、不带 `.lean` 的逗号分隔路径，给出预期的函数证明。 |
| 可选标记 | `same:` 解释等价性；`gap:` 记录仅供开发使用的覆盖缺失。两者都不允许出现在必需的公开变异记录中。 |

有用的变异会删除检查或赋值、改变边界或比较、修改索引或移位，或返回错误结果。应选择已证明函数的不同部分。语法错误，或仅破坏源码相等性引理的变异，不足以构成其执行契约的证据。

已提交的 `tests/audit/proofmut/` 下的列表覆盖校验、工具函数、树、inflate、deflate 和解码表证明组。其他列表位于 `tests/proof-mutants/` 和 `tests/proofmut/`。文件和公开映射定义其精确范围；列表存在或某项历史结果，都不证明对应 C 文件中的每个函数已被覆盖。

## 运行器设置

`PROOFMUT_CACHE` 选择预热缓存。`PROOFMUT_TIMEOUT` 设置每次构建的秒数，默认为 3600。`PROOFMUT_KEEP=1` 保留临时副本；`PROOFMUT_SHOWLOG=1` 打印失败细节。`PROOFMUT_BASELINE=0` 跳过正构建，仅供局部诊断。`PROOFMUT_STRICT=1` 覆盖该跳过设置，并拒绝所有已知缺口。

最终接受会在严格模式下运行三个受支持目录中的每个列表。CI 也运行公开/模型变异命令。拟议的工作流片段或尚未执行的列表，都不能算作检查通过。当前覆盖工作记录在[概览](../overview.md)中。
