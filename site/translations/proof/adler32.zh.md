# Adler-32：有界求和与模运算精化

源码：固定版本的 `zlib/adler32.c`。对应模块为
`ZlibF/Zlib/adler32.c.lean`。
数学契约是 [格式指南](../format/README.md) 中的 `F-adler-incremental`。
[API 指南](../api/README.md) 规定空缓冲区、包装函数和组合运算。

本页解释 `adler32_z` 的论证，并不认证一项已登记的证明。
接受情况和当前范围记录在 [概览](../overview.md) 中。

## 单字节步骤保持什么

记 `B = 65521`、`NMAX = 5552`。
把输入累加器拆成 `a = adler & 0xffff` 和 `s = (adler >> 16) & 0xffff`。
对字节 `b`，数学步骤为

```
α' = (α + b) mod B
σ' = (σ + α') mod B
```

未经约简的机器步骤是 `a' = a + b; s' = s + a'`。
若机器求和尚未回绕，则 `a ≡ α (mod B)` 和 `s ≡ σ (mod B)`
蕴含该步骤之后仍满足相同的同余关系。
随后对 B 取模，就能恢复精确的数学数对。

因此，证明分为两个不同部分：机器安全地遍历正确的字节，
并且在所述起始值定义域上，机器求和精化模递推关系。

## 读取与终止

对于指向活字节对象的非空缓冲区，要求整个请求区间
`[off, off + len)` 可读。消耗 `k` 个字节后，
使用如下不变量：游标为 `off + k`，剩余计数为 `len₀ - k`，且 `k ≤ len₀`。
每次读取都在 `k < len₀` 时发生。
每次指针递增后的终点都不超过 one-past 位置。

| 分支 | 消耗的字节 | 度量 |
| --- | --- | --- |
| `len == 1` | 一个字节 | 无循环 |
| `len < 16` | 字节循环体每次消耗一个 | 测试前的剩余计数 |
| 完整批次 | `347 × 16 = 5552` | 剩余批次数和展开后的分组数 |
| 尾部 | 先按 16 个分组，再逐字节处理 | 剩余计数 |

后减测试可能在最后一次失败的测试中，使局部无符号计数器回绕。
证明必须精确建模该测试；回绕后的值不意味着还会执行一次循环体。
度量既要建立数学终止性，也要建立翻译后的 fuel 界。

单字节快速路径在空缓冲区检查之前。
初始化查询要求 `buf == NULL` 且 `len == 0`；它们返回 1，不读取内存。
其他调用要求一个可读的非空区间。
该函数不写入调用者内存，也不分配块。

## 默认构建中的批次为什么不回绕

两次约简之间最多有 5552 个字节步骤。
从 16 位分量开始，经过 `j` 个这样的步骤后，一个方便使用的界为

```
a ≤ 65535 + 255 j
s ≤ 65535 + j (65535 + 255 × 5552)
```

当 `j ≤ 5552` 时，这给出 `a ≤ 1481295` 和 `s ≤ 8224215375`，均小于 `2^64`。
因此，默认 LP64 的 `unsigned long` 加法与普通自然数算术一致。
这个宽松的界专用于 64 位论证；其他字宽需要为相应分支给出适合的界。

16 字节展开将单字节步骤不变量保持十六次。
把它应用于每个完整批次和尾部，然后约简，
就得到打包为 `a | (s << 16)` 的结果。
移位和打包也需要各自的机器字宽界。

## 精确的起始值范围

正常的增量校验和从已经约简的分量开始。
公开函数也接受整数累加器，因此正确性命题必须说明如何解释非规范分量。

在短分支中，低分量满足
`a ≤ 65535 + 15 × 255 = 69360 < 2B`；一次条件减法就能将其约简。
高分量对 B 取模。在单字节分支中，两个分量都只执行一次条件减法。
这样约简高分量，要求传入的 `s < B`，
因为新的低分量小于 B，此时两者之和小于 `2B`。

因此，直接的递推论证在 `len ≠ 1` 时覆盖任意累加器字，
而在单字节情况下，覆盖传入高分量小于 B 的情形。
它还必须单独处理空缓冲区的返回。
这是该论证的范围，并不授权缩小固定的公开目标。

这个区别可以被观测到。
对于 `adler32_z(0xFFFFFFF0, "\0", 1)`，掩码后的低分量为 65520，高分量为 65535。
字节步骤之后，两者之和为 131055。
一次减法留下 65534，函数返回 `0xFFFEFFF0`。
完整的模约简会得到高分量 13。
该调用内存安全；如果规格把每个任意起始字都完整约简，就会给出不同的值。
审查精确契约时应保留这个反例。

## 包装函数与组合

`adler32` 转换长度参数之后，沿用该字节算法。
`combine` 函数需要单独的算术证明：
为连接操作展开两个运行中的和，计入初始值修正，
并表明翻译后的约简计算出该公式。
对有符号长度的拒绝和字宽转换属于各自的 API 契约。
这些不能从 `adler32_z` 的内存安全性推出。

更早的工作为字节算法给出过 Lean 论证。
复用时，需要对照当前模块，检查其命题、机器字宽、所选补丁、执行关系和前提。
非空泛性和变异要求见 [方法](method.md)。
