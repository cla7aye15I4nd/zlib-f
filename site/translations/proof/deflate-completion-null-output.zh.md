# NULL 输出与完成目标

在输出指针修正之前，完成命题为假。
这是一个规范域错误，而非 zlib 缺陷。此前审查过的
FINISH_STATE 中无新输入条件并未排除此情况。
当前状态和剩余工作记录在[概览](../overview.md)中。

## 精确的 Lean 反证

[已归档的 Lean 复现](deflate-completion-null-output.lean.txt)
针对提交 `3f816a0cad822cb564f6156b8f16ad2d98def9dc` 证明了
`¬ DeflateCompletes` 和 `¬ Goal.deflate_sequence`。其三个导入和被反证的目标
与在 `f6376b0f2bbc2184e9ec472197768eb0b1916d12` 处经过检查的发布预算扩展一致，
该提交是复现被编译的位置。两个声明仅使用 `propext`、`Classical.choice` 和
`Quot.sound`。该复现构造了一个真实的默认初始化历史；
它不假设任何被调用方执行契约或不可达的私有状态。

调用者具有空输入、NULL 输出和 64 的输出计数。实际的
init 建立了 DGood 并保留了这些公共字段。空数据
轨迹未完成且符合边界条件。StreamBuffers 成立，因为其
CallerRange 明确允许 NULL，包括具有非零
计数的错误调用。ActiveHeader 和可读的空输入快照成立。
FINISH 输入条件成立，因为 avail_in 为零。空
输入的边界为 13，至多为 64。因此所有当前完成前提均成立。
被证明的实际公共拒绝返回 STREAM_ERROR，与
所需的 STREAM_END 相矛盾。

已归档的复现刻意命名了未修正的目标。它是
历史证据，一旦新的输出指针前提被批准，它将不再针对该目标
通过类型检查。它不作为实现目标的证明被导入。若要重新检查，请将文本复制到
所述修订版本上的临时 Lean 文件，并使用项目环境编译它。

## 固定版本的 C 复现

[C 复现](deflate-completion-null-output.c) 执行普通的
默认初始化和相同的空输入 FINISH 调用。针对固定源
`757f0527154291bcf6bfbd6396ecde6bedd2db95`，使用地址和
未定义行为 sanitizer构建，它以零退出并打印：
```text
init=0 bound=13 capacity=64 finish=-2 total_out=0
```
未观察到任何 sanitizer 诊断信息。该返回是源代码中显式的 NULL 输出拒绝。本次运行是 C 语言行为的证据，而非翻译保真度的证明。Lean 的反证提供了形式化模型的结果。

## 最小化建议修正

仅在 DeflateCompletes 中，在现有的 FINISH 输入条件之前，添加 `z.next_out ≠ .null`。保持 StreamBuffers、所有数据跟踪构造器、序列安全性、运行时和翻译不变。带有 NULL 输出的安全错误调用仍由安全性和编码观察覆盖。它们不属于成功完成的承诺。

这改变了完成命题，因此也改变了 Goal.deflate_sequence 中其合取项的含义。这需要明确的人工授权以及重新生成并经过审查的审计锁。人工审查已单独授权了这一确切的额外前提及其审计锁的重新生成。该前提已应用。之前的 FINISH 输入条件保持不变。生成锁的审查和实际的完成证明仍然需要。

## 入口拒绝审计

实际的 deflate 入口守卫已针对完成性进行了联合审查：

| 守卫 | 现有或建议的理由 |
| --- | --- |
| 无效流或私有状态 | 来自实际被接受历史的 DGood |
| 超出其范围的刷新 | 定理调用固定的 Z_FINISH |
| NULL 输出 | 缺失；建议非 NULL 前提 |
| 具有正输入计数的 NULL 输入 | 被可读的 Bytes 快照排除 |
| 具有不同刷新的 FINISH_STATE | 对于固定的 Z_FINISH 是不可能的 |
| 零输出容量 | 被现有的正容量前提排除 |
| 重复的非 FINISH 拒绝 | 显式排除 Z_FINISH |
| FINISH_STATE 后的新输入 | 被已批准的输入条件排除 |

这是对拒绝守卫的源代码级审计。它不证明全局输出充分性、所有配置或修正后的完成目标。

## 生成锁比较

在修正后的源上，新的重新生成通过：1008 个作业的完整构建，27,864 个声明和 400 个列出定理的新内核重放和声明审计。覆盖率保持为 181 个目标中的 78 个。本地无占位符检查也通过。这些是本地检查，而非绿色 CI。

与经过审查的 FINISH 输入条件父提交 `3f816a0` 相比，所有 7,991 个语义声明名称均保留。只有 DeflateCompletes 的值指纹发生变化。其类型保持为 Prop。注册的定理类型、注册项和编译器辅助例外在字节级别完全相同。策略差异仅涵盖 Sequences.lean 和重新生成的语义锁指纹。没有锁被手动编辑。Goal.deflate_sequence 的直接指纹保持不变，因为它引用 DeflateCompletes；其完成合取项有意具有新的含义。经过审查的语义变化不得被描述为保留了每个目标的含义。

独立的基线审查和对组合集成提交的检查仍然需要。没有新证明的实现完成定理。
