# 工具函数：分配与常量查询

源码：`zlib/zutil.c` 和 `zlib/zutil.h`；翻译：
`ZlibF/Zlib/zutil.c.lean`。这些函数同时支持两个流实现。
其公开契约见 [API 指南](../api/README.md)，
其所有权作用在 [安全要求](../safety.md) 中定义。

尽管名为 `zcalloc`，默认 LP64 分配器分支使用的是 `malloc`。
它不会把块清零。初始化证明必须建立所需的字段写入，
包括模型没有跟踪的指针写入。

## 调用者处的尺寸算术

在这个分支中，`zcalloc(opaque, items, size)`
以 32 位 `unsigned` 算术计算 `items * size`。
其包装函数定理必须忠实描述该乘积。
调用者若期望普通乘积，就必须在依赖分配所得容量之前，证明它小于 `2^32`。

| 默认流分配 | 最大乘积，以字节计 |
| --- | --- |
| `deflateInit2_` 状态 | LP64 `sizeof(deflate_state)` |
| 压缩器窗口：`w_size * 2` | 65536 |
| 压缩器 `prev`：`w_size * sizeof(Pos)` | 65536 |
| 压缩器 `head`：`hash_size * sizeof(Pos)` | 131072 |
| 压缩器 pending 缓冲区：`lit_bufsize * 4` | 131072 |
| `inflateInit2_` 状态 | LP64 `sizeof(inflate_state)` |
| 解码器窗口：`(1U << wbits) * 1` | 32768 |
| `deflateCopy`, `inflateCopy` | 上述相应状态和缓冲区尺寸 |

状态尺寸必须来自所选 ABI 布局，并与 C 布局检查一致。
它们不是跨配置不变的数学常量。
缓冲区界来自已验证的参数，以及流不变量中保留的尺寸等式。
这个表只讨论列出的流分配，
并不为每条 gz 或其他 API 路径断言最大分配量。

## 成功与失败的效果

成功时，分配增加一个具有模型尺寸的新鲜活块。
失败时，它返回空指针，不增加活块。
无论哪种情况，都不能让一个尚未写过的新指针字段可以安全读取。
根据 [运行时规则](../safety.md#uninitialised-memory)，未初始化整数具有任意值。

`zcfree` 接受空指针或分配器接口允许的块。
非空释放要求相应的活所有权断言。
结束和失败清理证明必须恰好提供它一次。
堆保存存活性和分配历史；证明中的 `Owns` 关系把活块分配给流。

`deflateInit2_` 分配一个状态和四个缓冲区。
组合的缓冲区失败检查位于各缓冲区分配之后，
因此早先一次分配失败，不意味着后续分配从未尝试。
清理必须释放这次尝试中所有成功的分配，
按源码规定清空或保留字段，并恢复之前的活块集合。
`inflateInit2_`、延迟的解码窗口分配和两个复制函数，
都需要各自的失败情况组合。
仅靠分配器包装函数，不能证明这些生命周期清理中的任何一项。

## 常量与错误查询

| 函数 | 所需结果与框架 |
| --- | --- |
| `zError(err)` | 超出范围的分支选择条目 9。否则有 `-6 ≤ err ≤ 2`，因此 `2 - err` 位于 `[0, 8]`，且无有符号溢出。返回十元素消息表中的精确条目；保持堆不变。 |
| `zlibVersion` | 返回所选版本字符串指针，具有契约要求的静态内容；保持堆不变。 |
| `zlibCompileFlags` | 从所选类型宽度和启用的源码分支推出精确的数值标志；保持堆不变。 |

常量返回仍是精确契约：
错误的版本指针或改变的标志位，必须使函数的证明变异测试失败。
更早的文档曾把这些包装函数归为先前模型中的已完成项。
当前结果要求 [检查](../checking/README.md) 所描述的精确目标、登记、变异证据和经审查的 CI。
当前检查点见 [概览](../overview.md)。
