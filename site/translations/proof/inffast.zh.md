# 快速解码：余量、历史与源位

源码：`zlib/inffast.c`；翻译：`ZlibF/Zlib/inffast.c.lean`。
契约术语是 [内部契约](../design/internal-contracts.md) 中的 `I-if-*`。
表谓词来自 [表构造](inftrees.md)。窗口不变量 W 在
[流式解码](inflate.md) 中说明。

这是一个内部函数。以 `I-if-pre-*` 为前提的定理，不能证明所有合法的
`inflate` 调用都会建立这些前提。源位保持结果也需要连接到独立的格式语义。
这些结果的当前范围见 [概览](../overview.md)。

## 入口视图与循环不变量

`I-if-pre-room` 给出模式 `LEN`、至少六个输入字节和 258 个输出字节的空间，
以及外层 `inflate` 调用在同一输出对象中先前产生的可读输出前缀。
输入与输出不相交。`I-if-pre-bits` 给出 `bits < 8`，并确定 `hold`
恰好表示缓冲区低位中的那些位。`I-if-pre-tables` 提供已初始化且具有含义的
根表和子表表项。`I-if-pre-window` 提供有效历史，以及默认的 sane 距离检查模式。

源码形成以下指针：

```
last = in + (avail_in - 5)
end  = out + (avail_out - 257)
beg  = out - (start - avail_out)
```

这里的 `beg` 是外层调用输出的起点，不一定是本次快速调用输出的起点。
前置条件必须针对实际缓冲区视图，论证这个指针减法的有效性。
用 `in0`、`out0` 表示快速调用的游标。

在每次进入循环体时，使用以下具名不变量：

| 名称 | 内容 |
| --- | --- |
| I1 | `in0 ≤ in ≤ in0 + avail_in`；循环余量保证游标处有六个可读字节。 |
| I2 | `out0 ≤ out`；循环余量保证游标处有 258 个可写字节。 |
| I3 | `hold < 2^bits`，循环体内位数至多为 30，入口位数小于 8。 |
| I4 | `beg ≤ out`；区间 `[beg, out)` 已由外层调用产生。 |

第一次循环体由 `do` 循环直接到达，因此入口前提必须直接提供其余量。
后续循环体使用 `in < last && out < end`。

## 位数与六字节界

对于一个长度和距离对，有四处补充位缓冲的位置。

| 位置 | 守卫与读取量 | 可用的界 |
| --- | --- | --- |
| R1，长度查表之前 | `bits < 15`：读取两个字节 | 补充后有 16 到 30 位。 |
| R2，长度额外位 | `bits < op`、`op ≤ 5`：读取一个字节 | 补充后至多有 12 位。 |
| R3，距离查表之前 | `bits < 15`：读取两个字节 | 补充后有 16 到 30 位。 |
| R4，距离额外位 | `bits < op`、`op ≤ 13`：至多读取两个字节 | 带守卫的补充操作保持位数至多为 28。 |

若跳过 R1 或 R3，则已经至少有 15 位可用。
表的含义把一个完整编码——包括可能的子表查找——限制在 15 位以内。
R2 为至多五个额外位提供足够的位；R4 为至多 13 个额外位提供足够的位。
因此，每次 `bits -= op` 都只移除已有的位。补充操作保持 I3，
相关移位也都在机器位宽之内。

把各处的最大值独立相加，会允许读取七个输入字节。但这种组合不可能发生。
假设 R1、R2、R3 和 R4 分别读取 2、1、2 和 2 个字节。
经过 R1 和至多 15 位的长度编码后，至少还剩一位。
经过 R2 和至多五个长度额外位后，至少还剩 `1 + 8 - 5 = 4` 位。
经过 R3 和至多 15 位的距离编码后，至少还剩 `4 + 16 - 15 = 5` 位。
R4 若要读取第二个字节，则第一次补充之前必须少于五位，因为即使第一次补充后
也仍然少于 `op ≤ 13` 位。矛盾。

因此，每次循环体至多读取六个字节。这就是 `last` 减去五个字节的原因。
一个字面量写出一个字节；根据长度表的基值和额外位解释，一个匹配至多写出 258 个字节。
这论证了 `end` 中减去 257 个字节的依据。空间界依赖表的语义，
不只是已分配的表容量。

## 表读取

根索引 `hold & ((1 << rootbits) - 1)` 小于 `2^rootbits`。
T2 提供相应表项已初始化的事实。链接提供有界的子表区间；
经掩码处理的子索引位于该区间内。表谓词还必须建立表项的操作、码长、
基值和额外位范围，以及二级表项不是另一个链接的事实。
于是 `goto dolen`/`dodist` 路径在至多一次链接查找后终止。

保留符号到达正确的错误退出路径。块结束到达调用者契约规定的模式转移。
这些退出仍然需要对游标、位缓冲和状态的影响作精确描述。

## 匹配复制：F3 和 F4

令 `done = out - beg`，`dist ≥ 1` 为解码出的距离，
`3 ≤ len ≤ 258` 为匹配长度。

若 `dist ≤ done`，源从 `out - dist ≥ beg` 开始。
复制按顺序进行：在第 k 步，源是相对位置 `k - dist` 上已经产生的字节。
即使源区间和目标区间重叠，该字节仍位于目标之前。这就是 DEFLATE 的重复规则；
若把循环替换成要求复制不相交的论证，就会丢失这条规则。

若 `dist > done`，设置 `op = dist - done`。sane 距离检查拒绝 `op > whave`。
检查通过后，`1 ≤ op ≤ whave ≤ wsize`，因此已分配的窗口含有所需的更早历史。
其源有三种形状：

| 条件 | 初始窗口索引 | 边界论证 |
| --- | --- | --- |
| `wnext == 0` | `wsize - op` | 复制到环的末尾。 |
| `0 < wnext < op` | `wsize + wnext - op` | 先复制 `op - wnext` 个字节到末尾，再从索引 0 开始复制至多 `wnext` 个字节。 |
| `wnext ≥ op` | `wnext - op` | 在当前环形游标之前复制。 |

每一段只复制其历史字节数与剩余匹配长度中较小的量。
若匹配长度超过窗口提供的部分，剩余源就位于本次调用已经产生的输出中，
此时应用顺序复制的论证。要证明展开后的循环次数完全准确，
包括每个 `do … while (--op)` 的初始计数都为正。

F4 表示 `whave < wsize` 蕴含 `wnext = whave`。
在尚未满的环中，只有第三种形状可能出现；它的源位于已初始化的历史中。
在已满的环中，所有字节都是历史，因此跨尾部回绕的形状有效。
更强的功能不变量必须确定这些字节对应逻辑输出与字典历史的后缀。

## 回退与最终写回

退出时退回推测性读入的完整输入字节：

```
len = bits >> 3
in -= len
bits -= len << 3
hold &= (1U << bits) - 1
```

若本次快速调用读取了 B 个字节，记账不变量给出
`bits ≤ bits_entry + 8B < 8 + 8B`。因此 `len ≤ B`，回退绝不会早于 `in0`。
结果中缓冲的位少于八位，所以最后的掩码移位有效。
随后，函数把精确的剩余输入和输出计数、游标、`hold`、`bits`
以及到达的模式写回流中。

`bits_entry < 8` 至关重要。没有它，回退可能退还本次快速调用从未读取过的字节。
**to confirm**：主解码器在进入这条快速路径的每个实际转移或调用上都建立这个前提，
包括恢复执行的调用，以及固定表和动态表的安装。
如果不检查这些路径和缓冲区视图，仅对补充和丢弃宏作一般性观察并不足够。

## 从安全到解码

功能循环不变量必须确定已消耗的低位与原始源流的关系，并把产生的字面量和匹配
联系到独立的格式符号。要在长度和距离选择、额外位读取、全部复制形状、
链接表、结束和错误退出、回退以及最终写回中保持这层关系。
源关系必须经受整个循环体和整个调用的组合，不能只覆盖一个成功的局部 token。

内部的源位来源引理可以在其声明的定义域上确定所选位的精确值。
把这些结果连接到初始化建立的状态、已安装的表、所有合法调用者视图，
以及独立输出语义，是另一个精化义务。支撑解码符号的那些字节，
不会自动为推测性预读提供依据；因果性上的这一区别在
[inflate](inflate.md) 中说明。

对于终止性，一个循环体要么至少写出一个字节，要么因结束或错误而退出。
有限的输出范围界定继续执行的循环体次数。复制循环和链接查找也有有界度量。
要把这些界换算到实际 fuel 预算，并在每次退出时保持框架条件。
这里不发生分配；现有状态和窗口的所有权保持不变。
