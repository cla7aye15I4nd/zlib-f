# 解码表：从码长到已初始化的表项

源码：`zlib/inftrees.c`；翻译：`ZlibF/Zlib/inftrees.c.lean`。
内部术语是 [内部契约](../design/internal-contracts.md) 中的 `I-it-*`。
数学目标是 [格式指南](../format/README.md) 中的 canonical code 关系 `F-code-*`。

核心证明有三层：码长描述一个 canonical 前缀码；构造过程写出有界的表；
实际堆表项实现该编码，包括无效标记。只有最后一层才能论证
`inflate` 和 `inflate_fast` 所使用的表谓词。以下论证是一种证明策略；
[概览](../overview.md) 记录哪些连接已获接受。

## 定义域与结果

`I-it-pre-lens` 提供 `0..15` 范围内的可读码长。对于 `CODES`，码长至多为 7，
且请求的根表宽度至少为 7。`I-it-pre-codes` 将 `CODES`、`LENS` 或 `DISTS`
的符号数分别限制在 19、288 或 32 以内。`I-it-pre-work` 提供可写且不相交的
临时空间。`I-it-pre-table` 提供可写的表指针和根宽度单元，以及与它们不相交的
表区域；对于相应类型，区域分别有 128、852 或 592 个表项。

早先笔记中称为 **T1** 的安全目标，是在这些内部前提下，所有返回路径都终止
且不发生故障：0 表示成功，-1 表示码长无效，1 表示表容量不足。
精确契约必须描述每种返回中的部分写入和参数单元影响。失败不承诺堆保持不变。

成功表目标 **T2** 给出根表和子表表项的覆盖性、有界链接，以及每个可达表项的含义。
全零码长和允许的单符号不完整编码都需要明确分情况处理。
调用者还需要实际指针推进量和返回的根表宽度。

## 计数与 Kraft 检查：F1 和 F2

令 `c_l` 统计正码长 `l` 的符号数，`m = Σ c_l`；当 `m > 0` 时，
令 `min` 和 `max` 分别为第一个和最后一个存在符号的码长。
把请求的根宽度限制到这个范围后，得到 `min ≤ root ≤ max ≤ 15`。

将长度为 `l` 的第一个 canonical code 定义为：

```
B_l = Σ_{1 ≤ j < l} c_j 2^(l-j)
B_1 = 0
B_(l+1) = 2 (B_l + c_l)
left_l = 2^l - B_l - c_l
```

有符号的 Kraft 循环保持 `left_0 = 1` 和
`left_l = 2 left_(l-1) - c_l`。结果为负时，它拒绝输入。
因此通过检查可得 `B_l + c_l ≤ 2^l`，从而每个分配的长度为 l 的码都能用 l 位表示。
证明还必须界定有符号的中间值。

最后的不完整编码检查，只有在类型不是 `CODES` 且 `max = 1` 时才允许正的剩余量。
此时，一个非空的不完整编码恰有一个长度为 1 的符号。
这个例外对覆盖性论证至关重要；它不是完整的 Kraft 划分。

计数偏移从 `offs[1] = 0` 开始，并满足 `offs[l+1] = offs[l] + c_l`。
长度为 l 的第 i 个符号写入 `work[Σ_(j<l) c_j + i]`，其中 `i < c_l`。
该索引小于 `m ≤ codes`。不同符号占据不同槽位，因此 `work[0..m)`
已初始化，并按 `(length, symbol)` 排序。这就是 **F2**。
它同时给出索引界和随后读取 `work[sym]` 的含义。

## 反转编码的遍历

令 `rev_l(v)` 反转 v 的 l 个位。主循环不变量确定当前符号满足
`huff = rev_len(B_len + i)`，并给出 `huff < 2^len`。

在第一个正码长处，第一个 canonical code 为零。对于相同码长的后继，
递减的掩码清除反转码字前部连续的 1，并把紧接着的 0 置为 1，
其效果是普通二进制递增的位反转。若码字全为 1，则回绕到零。
当下一个存在符号的码长更大时，canonical 递推在普通编码的低位附加零。
反转后这些变成高位的零，因此 `huff` 在新宽度下仍保持正确的值。

对于完整编码，最后一个普通编码为 `2^max - 1`；最后一次反转递增的结果为零。
对于单符号例外，结果为 1。这些事实决定尾部的无效标记写入是否发生。

## 重复填充与子表大小

对于 `len ≤ root` 的根表表项，填充循环写入以下索引：

```
huff + (2^root - 2^len), …, huff + 2^len, huff
```

由于 `huff < 2^len`，所有索引都小于 `2^root`。
填充计数是 `2^len` 的倍数，因此递减会在零处结束而不发生回绕。
这些恰好是低 len 位与反转编码相匹配的索引。

对于 `len > root`，一个根前缀 p 把连续的普通 canonical code 归为一组。
确定子表大小的循环以 `curr = len - root` 和 `left = 2^curr` 开始，
减去当前深度的剩余码数，并在向下深入时把空闲槽位翻倍。
若该深度的剩余码数少于 p 下的空闲槽位数，这些码就全部属于 p。
若这些码填满了槽位，该前缀在此深度就是完整的。循环也会在 `max` 处停止。
这个计数论证必须建立：p 下的每个码都满足 `len - root ≤ curr`。

在 `drop = root` 下，重复填充随后在有 `2^curr` 个表项的表内使用
`2^(len-drop)` 的步长。整除性和 `huff >> drop < 2^(len-drop)` 给出
与根表重复填充相同的界。前瞻计数在其最后一个深度可能包括后续前缀的码；
证明必须论证，即便如此，其停止条件对当前前缀仍然充分。

## 容量与指针形成

`used` 从 `2^root` 开始，每加入一张子表就增加该子表的 `2^curr`。
当前的 `next` 指针等于表基址加上此前各表的容量。
`LENS`/`DISTS` 的检查在新子表被写入或链接之前，拒绝超过 852/592 的容量。
检查之前的指针形成和算术，仍需要从此前的预留空间得到各自的尾后界。

`CODES` 没有这样的容量检查。它对码长和根宽度的更强前提保证
`max ≤ 7` 且 `root = max`，因此不会建立子表，使用的表项至多为 128 个。
其他类型的守卫论证不能代替调用者的这个前提。

常数 852 和 592 来自穷尽的表大小分析。只要这些检查之前的所有操作都是安全的，
显式检查就足以保证选定构造过程的安全。证明每一种合法格式编码都被接受，
还需要另一个界：仅证明容量不足时会安全地拒绝，不能证明这种完备性性质。

根链接使用 `low = huff & (2^root - 1) < 2^root`，并存储子表宽度和偏移
`next - base`。要证明该偏移能装入它的 16 位字段，且链接区间位于预留的表内。

## 覆盖性与含义：T2

对于完整编码，宽度为 `2^-len` 的叶区间划分了编码空间。
根表项要么位于一个短叶之下，由该叶的重复填充写入；要么包含更长的叶，
由其中第一个成员创建并链接子表。在该子表内部应用相同的区间论证。
叶区间互不相交，保证不同符号不会给同一个表项赋予冲突的含义。

对于单符号的不完整编码，`root = 1`：循环写入表项 0，尾部把表项 1 写为无效。
对于没有已编码符号的情况，单独的分支写入两个无效表项，返回宽度 1，
并把表指针推进两个位置。不能假装编码完整来论证这两种情况。

仅有覆盖性还不够。要证明 `op`、`bits` 和 `val` 的解释：字面量，
长度或距离的基值加额外位，块结束，无效标记，或子表链接。
还要建立经过一个链接时的总码长界，以及二级表项不是另一个链接的事实。
由 `inflate_fixed` 安装的固定表需要相同的读取者谓词，包括它们保留的无效符号。

## 其他局部附加条件

这些是 T1/T2 的组成部分，不是第二份进度记录。

| 操作 | 所需事实 |
| --- | --- |
| `count[lens[sym]]` | 码长至多为 15。 |
| `count[curr + drop]` | 确定子表大小的循环条件把这个和限制在 `max ≤ 15` 以内。 |
| 下一个 `work[sym]` 和 `lens[work[sym]]` | 循环继续时总有剩余符号；F2 给出其槽位的界和初始化事实。 |
| `LENS` 的基值或额外位访问 | 相关符号至少为 257，至多为 287，位于有 31 项的数组内。 |
| `DISTS` 的基值或额外位访问 | 符号至多为 31，位于有 32 项的数组内。 |
| `CODES` 的 null 基值或额外位指针 | 对于符号 `0..18`，选择这些指针的分支永远不会到达。 |
| 移位计数 | 正码长以及有界的根表、子表宽度，论证每个 `1 << k` 的有效性，包括 `len - 1` 和 `len - drop`。 |
| 循环终止 | 计数和排序循环有固定范围；主循环每次消耗 m 个符号中的一个；掩码递减和子表前瞻具有有界的位数或深度范围。 |
| 框架条件 | 只有获准的临时空间、输出表项和参数单元发生变化；静态基值和额外位数组保持只读。 |

纯粹的 canonical code 引理属于 `ZlibF/Math/`。
它们与翻译后存储、全部退出路径和已安装解码器不变量之间的连接属于执行证明。
[方法](method.md) 说明调用者如何在不假设被调函数契约的情况下，建立这些前提。
