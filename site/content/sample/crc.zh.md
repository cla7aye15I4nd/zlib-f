gzip 封装对未压缩数据使用 CRC-32。它和 Adler-32 一样，可以跨缓冲区继续，也可以组合独立分块。它的算术不同：每个位是 GF(2) 上多项式的系数，因此加法是 XOR，没有进位。

先理解逐字节含义。表、字读取和交织通道，是用不同依赖关系计算同一结果的方法。它们不会为对齐缓冲区或长输入定义另一种校验和。

## 反射寄存器 {#register}

底层多项式的次数为 32，表示中的最高项 `x^32` 是隐含的。zlib 的反射位约定使用常量 `0xedb88320`：寄存器向低位移动，因此位步骤执行右移。如果移出的位为一，就把多项式常量 XOR 到右移后的寄存器：

```text
T(r) = (r >> 1) XOR (0xedb88320 if r & 1 else 0)
```

寄存器为 32 位值。消耗字节 `b` 时，先将它 XOR 到寄存器的低八位，再应用八次 `T`。字节的最低有效位先进入计算。

公开的运行中校验和与这个内部寄存器互为按位取反。新校验和从 0 开始。函数先对传入校验和取反，处理字节，再对结果取反。调用者将返回值直接传给下一次更新；再次自行取反会改变计算。

## 一个字节 {#one-byte}

对 ASCII A，`b = 0x41`。从公开校验和零开始，内部寄存器为 `ffffffff`。XOR 字节后得到 `ffffffbe`，再执行八个位步骤：

| 已完成位步骤 | 内部寄存器，十六进制 |
| --- | --- |
| 步骤之前 | `ffffffbe` |
| 1 | `7fffffdf` |
| 2 | `d2477ccf` |
| 3 | `849b3d47` |
| 4 | `aff51d83` |
| 5 | `ba420de1` |
| 6 | `b09985d0` |
| 7 | `584cc2e8` |
| 8 | `2c266174` |

第一步移出的位为零，因此只右移。下一步先把 `7fffffdf` 右移为 `3fffffef`，再 XOR `edb88320`，得到 `d2477ccf`。对第八步的结果取反，得到公开 CRC `d3d99e8b`。

继续处理 B 得到 `30694c07`。从零独立处理 B 得到 `4ad0cf31`；这是两个不同的任务。独立递推与固定版本 C 函数在这些例子上相符。这核对了展示数值，不覆盖全部输入。

## 字节表 {#tables}

八个位步骤是一项固定的线性操作。可以预先计算每个低字节的结果：

```text
table[i] = T⁸(i)
byte_step(r,b) = (r >> 8) XOR table[(r XOR b) & 255]
```

索引有 256 种可能。寄存器的高 24 位向下移动，表则提供低字节对应的多项式贡献。对 A，索引为 `be`，`table[be] = 2cd99e8b`。与 `00ffffff` XOR，仍然得到 `2c266174`。

[`get_crc_table`](/reference/functions/get_crc_table.html) 暴露这张字节表。条目描述内部寄存器更新，不包含公开接口的取反。返回的存储是静态只读的；该指针不授权读取相邻交织表、写入条目或释放数组。

## 字与交织 {#braids}

字节递推仍有一条长依赖链：每个新字节都需要上一个寄存器值。所选默认分支使用八字节字和五条交织通道。概念上，第零通道处理字位置 0、5、10……；第一通道处理 1、6、11……，以此类推。

这些是有间隔的子序列。相应表计入相邻通道字之间的多项式距离。第零通道接收预处理后的传入寄存器 `(~crc) & 0xffffffff`，其余通道从零开始。它们不是连续五个分块的普通校验和。最终块代码通过字递推，按原始字节顺序合并这些贡献。

阈值为 `5×8 + 8−1 = 47` 字节。最多七个字节用于达到对齐，至少留下一个 40 字节块。循环处理最后一块之前的所有块；独立代码处理最后一块及其合并。之后剩余不足 40 个字节，由展开的字节尾部和逐字节循环处理。

这样的组织暴露了相互独立的通道依赖，并分摊循环工作。字的端序和地址对齐仍是选择、解释实际读取的一部分。所选证明模型按目标端序组装相同字节；C 转换和 ABI 对应关系需要各自审查。

## 多项式算子 {#operators}

令 `T⁸ⁿ` 表示不带公开接口取反、让寄存器前进 `n` 个零字节。对于独立计算的 X、Y 校验和，取 `n = length(Y)`，有：

```text
CRC(X ++ Y) = T⁸ⁿ(CRC(X)) XOR CRC(Y)
```

在这个连接恒等式中，初始和最终取反的项相互抵消。不能通过对 `n` 个零字节调用公开更新函数来实现 `T⁸ⁿ`，因为那次调用会包含它自己的取反约定。

当 X=A、Y=B 时，`T⁸(d3d99e8b) = 7ab98336`。与 B 独立计算的 `4ad0cf31` XOR，得到 `30694c07`，即 AB 的 CRC。

前进操作是 32 位上的线性映射，可以用二进制矩阵表示，也可以用模 CRC 多项式的乘法表示。所选源码使用多项式乘法和 `x2n_table` 中预先计算的幂，通过反复平方按长度的位进行计算。它不逐个遍历 `n` 个字节，就能计算 `x^(8n)` 的算子。在这种反射乘法表示中，乘法单位元是 `0x80000000`。

## 校验和入口 {#entries}

[`crc32_z`](/reference/functions/crc32_z.html) 使用尺寸类型的长度；[`crc32`](/reference/functions/crc32.html) 使用 32 位计数。[`crc32_combine`](/reference/functions/crc32_combine.html) 和 [`crc32_combine64`](/reference/functions/crc32_combine64.html) 接受独立校验和与 Y 的有符号长度。

许多第二分块长度相同时，可用 [`crc32_combine_gen`](/reference/functions/crc32_combine_gen.html) 或 [`crc32_combine_gen64`](/reference/functions/crc32_combine_gen64.html) 一次生成算子，再通过 [`crc32_combine_op`](/reference/functions/crc32_combine_op.html) 复用。算子由生成函数产生是一项定义域要求，不是只要任意非零整数即可。

负长度生成零，并让组合调用返回零。真正的空 Y 的 CRC 为零，会保持 X 的校验和。若长度为零而参数是任意标量，实现则返回两者低 32 位的 XOR。NULL 更新查询即使长度非零也返回零。[证明章节](/sample/checksum-proof.html) 区分这些精确 API 情况与校验和连接，并解释内存视图假设。
