[输入位缓冲](/sample/input-bits.html) 能高效提供低位。解码表把它们解释成字面量、长度或距离基值、结束标记、无效标记，或者指向另一张表的链接。在解码器使用这张表之前，`inflate_table` 必须先从给定码长构造实际数组。

我们先跟踪构造算法本身，再讨论证明。四符号码 `A=0`、`B=10`、`C=110`、`D=111` 仍是一个小型教学字母表。真实 DEFLATE 调用使用码长、字面量/长度或距离字母表，各自具有不同的含义和限制。

## 码长计数与已占空间 {#counts}

[`inflate_table`](/reference/source/ZlibF/Zlib/inftrees.c.html#L243) 清零 `count`，然后对每个输入符号递增 `count[lens[sym]]`。零码长表示未使用。非零码长决定 `min` 和 `max`，请求的根表宽度被限制在这个已占范围内。

构造器随后检查这些码长能否放下。从一个可用根槽开始，每向下一层，把空闲槽翻倍，再减去放在该层的符号数：

```text
left = 1
for each length l from 1 through 15:
    left = 2 * left - count[l]
```

结果为负表示过度订阅，返回 `-1`。最终有正剩余量，表示编码不完整。源码不会接受所有不完整编码：除单独处理的空表外，仅在类型不是 `CODES`、且最大码长为一时允许正剩余量。被接受的非空不完整情形，恰有一个一位符号。

## 偏移与稳定符号顺序 {#ordering}

码长决定每层应有多少个码，但同层符号还需要确定顺序。`offs[1] = 0`，`offs[l+1] = offs[l] + count[l]` 给出每种码长在临时数组 `work` 中的起始槽位。

对码长 `[1,2,3,3]`，相关计数为 `[1,1,2]`，起始偏移为 `0,1,2`。按符号数值顺序扫描，把 A 写到 0、B 写到 1、C 写到 2，再把 D 写到 3。每次存储后递增该码长的偏移。C 和 D 保持符号顺序，因为扫描是稳定的；这里不需要比较排序。

若各符号码长以另一种次序出现，相同的计数过程仍会按码长分组，并保持每组中的符号数值顺序。随后主循环遍历这个已经初始化的 `work` 前缀。若把已递增的偏移与原来的起始值混同，就会丢掉这层连接。

## 表项字段与含义 {#entries}

主循环跟踪反转的 canonical code `huff`、其长度 `len`、当前表宽 `curr`，以及已经丢弃的根位数。对每个符号，它构造一个具有三个字段的 `code` 表项：

| 字段 | 含义 |
| --- | --- |
| `bits` | 当前表级需要消费的位数 |
| `op` | 字面量或直接值、基值加额外位、结束、无效或子表操作 |
| `val` | 符号值、长度/距离基值，或子表偏移 |

对字面量，`op = 0`，`val` 是对应字节。长度或距离基值使用操作标志及低位中的额外位数。块结束与无效标记具有不同的标志组合。链接用 `op` 表示子表索引宽度，用 `val` 表示相对原表基址的偏移。

所以，表项不只是一个符号编号。其字段同时控制解析器的控制流和位消费量。查表即使完全在界内，字段错误仍可能解出错误的流。

## 根表重复填充 {#replication}

根宽度为二时，A 的一位码必须占据低位索引 `00` 和 `10` 两个槽。B 占据 `01`。C 和 D 共享 `11`，该槽会成为链接。虽然查表查看两位，每个 A 表项仍只消费一位。

填充循环遍历低 `len` 位等于 `huff` 的索引，实现这种重复。它以 `2^len` 的倍数，在有 `2^root` 个槽位的区域内向下计数。编码遍历直接推进反转表示，不是反复反转整个输入。

## 子表构造 {#subtables}

当 `len` 超过根宽度时，构造器前瞻剩余码长计数，确定子表宽度。它统计当前根前缀下的空闲槽，减去编码数量，并在向下深入时翻倍。这样就不需要为每个前缀分配完整的最大深度树。

它把 `next` 推进到先前各表之后，把 `used` 增加 `2^curr`，再安装含有新宽度与偏移的根链接。子表内的重复填充先丢弃根位。对本例，额外的一位就能区分 C 和 D。

根表和子表属于同一段连续预留空间。指针、偏移、已初始化单元与返回的根宽度必须彼此一致。接下来的调用者使用本次实际返回的宽度，不能使用最初请求的宽度。

## 空输入、错误与预留空间 {#limits}

全零码长进入提前返回分支：写出两个一位无效表项，返回根宽度一，并把表指针推进两个槽。这里的成功表示表已经构造；尝试通过它解码仍会得到无效编码结果。被接受的单符号情形同样要求在有效槽之外明确写入一个无效槽。

对于 `LENS` 和 `DISTS`，容量检查保护 852 项和 592 项的预留量。inflate 状态在 `codes` 中预留两者之和 1444 项。这些是表项数量，不是字节数，也不是字母表大小。若要说明每种合法格式编码都会被接受，还需要另一个界；安全地拒绝容量不足，只说明构造器能够安全拒绝。

`CODES` 调用对码长和根宽度具有更强的前提：码长至多七，请求的根宽度至少七，因此不需要子表，至多使用 128 项。其他类型的容量检查不能代替这些前提。实际辅助函数定义域还包括保留符号；它们必须获得正确的无效解释。
