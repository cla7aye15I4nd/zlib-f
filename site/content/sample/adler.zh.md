压缩块描述怎样恢复字节。校验和回答另一个问题：恢复的这些字节，是否与流中的完整性字段一致？zlib 封装使用 Adler-32。它的输入是未压缩字节序列，不是 Huffman 码，也不是只看某次调用单独交付的那一段输出。

先让同一个 `ABABABAB` 例子经过两个小累加器，再区分两种操作：用下一段缓冲区继续计算，以及组合独立计算的两段校验和。它们都不要求把早先的字节保存在私有压缩窗口中。

## 两个累加器 {#accumulators}

令 `M = 65521`。从 `a = 1`、`s = 0` 开始，对每个字节值 `b` 计算：

```text
a := (a + b) mod M
s := (s + a) mod M
```

第二行使用更新后的 `a`。因此，`a` 累加字节值，`s` 累加连续的前缀和。经过 `n` 个字节后，不约简时的表达式是：

```text
a = 1 + b₁ + b₂ + ... + bₙ
s = n + n·b₁ + (n−1)·b₂ + ... + bₙ
```

约简之后，这些等式对应模 `M` 的同余关系。第二个和中的权重让字节顺序产生影响：交换 A、B 不改变第一个和，却通常会改变第二个和。

返回的校验和把约简后的 `a` 放在低 16 位，把 `s` 放在高 16 位，即 `a | (s << 16)`。这种数值布局与封装中的字节顺序是两件事。zlib 尾部按最高有效字节在前的顺序发送四个校验和字节。

## 八个字节 {#bytes}

ASCII A 为 65，B 为 66。这个短例子不需要约简：

| 已处理字节 | `a` | `s` | 打包校验和，十六进制 |
| --- | --- | --- | --- |
| 空 | 1 | 0 | `00000001` |
| A | 66 | 66 | `00420042` |
| AB | 132 | 198 | `00c60084` |
| ABA | 197 | 395 | `018b00c5` |
| ABAB | 263 | 658 | `02920107` |
| ABABA | 328 | 986 | `03da0148` |
| ABABAB | 394 | 1380 | `0564018a` |
| ABABABA | 459 | 1839 | `072f01cb` |
| ABABABAB | 525 | 2364 | `093c020d` |

第二个字节使 `a` 变成 `66 + 66 = 132`，使 `s` 变成 `66 + 132 = 198`。第二个累加器不是只加上新字节。因此，这八个字节对应的最终 zlib 校验字段是 `09 3c 02 0d`。

## 批次与约简 {#batches}

每次加法后都取余没有必要。zlib 可以在有界数量的字节内保留尚未约简的机器和，再在边界处约简两个和。整个过程中同余关系保持不变；还缺少的条件是：约简之前，机器加法不能溢出。

源码选择 `NMAX = 5552`。从已约简的分量开始，每个字节最多为 255，其可移植的第二个和的最坏情况界为：

```text
s ≤ (n + 1)(M − 1) + 255·n(n + 1)/2
```

当 `n = 5552` 时，右侧为 `4294690200`，小于 `2^32 − 1`。当 n 为 5553 时，它变成 `4296171735`，超过该上限。这解释了批次大小的来源；它不是任意选出的调优常量。

每个完整批次执行 347 组，每组 16 个字节步骤。展开分组减少循环开销，同时保留每个新 `a` 到 `s` 的依赖。余下的数据先按 16 个字节分组，再逐字节处理。独立的短输入和单字节路径避免不必要的准备工作。

所选 LP64 构建中的 `unsigned long` 和更宽，但实现保留相同的批次大小。另一个可选源码分支利用 `2^16 ≡ 15 (mod 65521)` 替代除法。该恒等式解释了为何可以把高位折回低位，却不表示那个分支属于这里描述的默认执行。

## 缓冲区边界 {#chunks}

处理下一个缓冲区时，把上一次校验和作为种子传回。第一次调用结束不会重置两个累加器。以正常种子 1 开始，先更新 A，再更新 B，就得到 AB 的普通校验和。

因此，应用输入的拆分点不必与批次边界一致。一次调用可以在一个字节后结束，下一次继续使用打包、约简后的两个和。校验和状态描述已接收的字节，不描述它们由多少次调用提供。

校验和函数自身不分配、不保留调用者指针，也不写入输入。外层压缩器或解压器另外决定哪些新处理的字节应计入封装校验和。

## 独立分块 {#combination}

假设 X、Y 分别从 1 开始计算校验和。将其分量记作 `(aX,sX)`、`(aY,sY)`，令 `n` 为 Y 的字节长度。则模 `M` 有：

```text
aXY = aX + aY − 1
sXY = sX + sY + n·(aX − 1)
```

减一去掉 Y 多带的一份初始值。长度项表示：X 的字节和会对 Y 中每一个新前缀作出贡献。这里需要的是 Y 的长度，不是 X 或两者之和。

当 X=A、Y=B 时，分量分别为 `(66,66)`、`(67,67)`。取 `n=1`，结果为 `(132,198)`，仍是 `00c60084`。Y 很大时，实现先把它的非负长度模 65521 约简，不需要扫描 Y。Adler 组合使用这种带长度权重的算术，而不是 [CRC-32](/sample/crc.html) 使用的多项式幂。

## 校验和入口 {#entries}

[`adler32_z`](/reference/functions/adler32_z.html) 使用尺寸类型的计数；[`adler32`](/reference/functions/adler32.html) 使用 32 位计数。大计数应使用多个更新调用或更宽的入口，不应先截断。

[`adler32_combine`](/reference/functions/adler32_combine.html) 和 [`adler32_combine64`](/reference/functions/adler32_combine64.html) 使用 Y 的有符号长度，组合独立开始的校验和。负长度返回 `0xffffffff`。真正的空 Y 校验和为 1，会保持 X 的校验和。

精确的 NULL 和任意种子情况很重要：本项目的 Adler 初始化查询要求 NULL 配合零长度。伪造种子不一定遵循规范的单字节递推。[校验和证明章节](/sample/checksum-proof.html) 解释这些定义域，以及上述等式怎样连接到实际内存和机器算术。
