## 从字节处理到应用程序 {#connection}

[压缩](/sample/blocks.html)把原文变成编码，[解压](/sample/decode-copy.html)再把编码恢复成字节。[流式调用](/sample/stream-state.html)允许这个过程暂停：输出空间用完后，保存状态，换一块空间继续。应用程序还要决定另一件事：**谁来提供这些缓冲区，谁来控制下一次处理？** 接口的选择从这里开始。

仍以八字节 `ABABABAB` 为例。如果原文和目标空间已经都在内存里，一次工具调用就可以完成任务。如果数据来自一个自定义容器，应用可以提供读取回调，让解码器主动索取片段。如果数据来自 gzip 文件，则可以把文件读取、解码和缓冲一起交给 `gzFile`。它们是不同任务的选择，不是同一条执行中的三站。

## 按输入来源和控制方式选择 {#choices}

| 应用程序手里有什么 | 由谁控制处理 | 交付什么结果 | 对应入口 |
| --- | --- | --- | --- |
| 逐步到达的字节；希望自己更换输入与输出区 | 应用循环调用 `deflate` 或 `inflate` | 每次调用的已读、已写前缀和可继续的状态 | [直接使用流式接口](/sample/interfaces.html) |
| 完整原文或完整 zlib 编码；目标容量已知 | 工具函数建立临时流并运行内部循环 | 目标字节、实际长度；计数解码入口还返回输入消费量 | [完整缓冲区](/sample/buffers.html) |
| 自定义容器里的裸 DEFLATE 片段；能提供回调和解码窗口 | `inflateBack` 在一次调用中请求输入、交付输出 | 输出回调接收的字节，以及最后一块的未读输入 | [回调解码](/sample/callbacks.html) |
| 文件路径或描述符；希望读到未压缩字节，或写成 gzip | 应用发出文件请求，句柄管理缓冲与内部流 | 文件读写结果、逻辑位置和错误状态 | [gzip 文件](/sample/gzip.html) |

格式与控制方式要同时匹配。缓冲区解码工具处理 zlib 封装；`inflateBack` 只处理裸 DEFLATE；gzip 文件接口还负责 gzip 成员和文件行为。直接流式接口可以通过初始化参数选择封装。它们不能仅凭“都在解压”就互相替换。[封装的布局](/sample/wrappers.html#layout)解释这些输入字节有什么不同。

## 同一种格式能力，不同的调用责任 {#engines}

完整缓冲区工具把普通流式协议收在函数内部。以压缩 `ABABABAB` 为例，调用者只提供一次源地址和目标容量，工具函数负责下面这段过程：

<ol class="bk-route-flow">
<li><strong>建立临时流</strong><span>初始化编解码状态，准备输入和输出切片。</span></li>
<li><strong>运行到完成或错误</strong><span>调用流式引擎，补充可用量，保留实际消费与产生的长度。</span></li>
<li><strong>结束临时状态</strong><span>释放内部资源，把长度和结果交回调用者。</span></li>
</ol>

因此，工具函数返回后没有可继续的流。gzip 句柄则把内部流保留在多次文件操作之间；一次 `gzread` 可以从文件读入更多编码，再只交付请求的原文字节。文件偏移与已交付原文位置因此会分开。

`inflateBack` 使用 `infback.c` 中独立的回调解码循环，并非在内部反复调用普通 `inflate`。它同样解析 DEFLATE 块、查表并按距离复制字节；区别在于输入由回调供应，解码窗口还直接作为输出回调的来源。[距离复制](/sample/decode-copy.html)中的字节含义不变，谁控制循环、哪些存储需要保持有效则改变了。

## 把返回结果接到证明 {#proofs}

选择接口，也就选择了应用程序能观察什么。完整缓冲区任务中，把 zlib 编码后接上 `END`，成功解码不仅要恢复八字节，还要把消费量停在 `END` 前。回调任务中，同样的八字节必须出现在接收成功的输出事件中，普通 `next_out` 计数不是交付凭据。文件任务又多了描述符、内部缓冲和关闭责任。

| 机制展开后留下的关键问题 | 对应证明 |
| --- | --- |
| 临时流是否正确写回长度，并在失败时释放已分配状态 | [缓冲区组合](/sample/interfaces-proof.html#buffers) |
| 回调改自己的数据时，活动输入与解码窗口是否仍然有效；有限输入如何保证终止 | [回调的保持条件与输入预算](/sample/interfaces-proof.html#callbacks) |
| 返回字节、逻辑位置、描述符位置与关闭后的资源是否一致 | [堆与文件世界](/sample/interfaces-proof.html#files) |
| 应用自己继续调用流时，上一轮状态怎样成为下一轮的合法起点 | [跨调用的证明](/sample/stream-proof.html) |

读者可以沿一项任务把机制与证明读完，再选择另一项任务。具体参数、拒绝条件、别名要求和错误后的可见结果保留在[完整 API 索引](/reference/api.html)；这些条件决定例子能推广到哪些调用。
